作品は、完成品だけではない。

作品のあとに、
何を残す？

つくったものだけ残すと、なぜそうなったかが消える。制作ログだけ残すと、肝心の作品が見えなくなる。そこで、創作の成果を4つの面に分けて、ひとつのパッケージとして辿れるようにする。

全部を一つの文書に潰さない。
01 / ARTIFACT作品実際につくったもの 02 / PUBLIC公開版他の人へ渡す物語 03 / PROCESS制作ログ選択・失敗・修正 04 / RETURN再利用できる知見次の制作へ持ち帰る

01. ARTIFACT — 作品

ゲーム、絵、文章、映像、サイト、プロトタイプ。説明ではなく、触れる／読む／見ることができる「もの」そのもの。

ARTIFACT ≠ 説明書 ≠ 制作記録。

完成度はCONCEPTでもGRAYBOXでもVERTICAL SLICEでもよい。重要なのは、どの版の作品なのかを後から辿れること。

02. PUBLIC EDITION — 公開版

note、紹介ページ、README、展示文など。「なぜ作ったのか」「どこが面白いのか」を、制作の外側にいる人へ渡すための文章。

毎回は作らない。 RELEASEや外部展示では基本的に用意する。途中段階では、制作途中そのものを見せたい時だけDEV EDITIONを作る。

公開記事を、作品や知見の正本にしない。

読みやすくするための省略や物語化はしてよい。でも、公開記事だけを読まないと制作を再開できない状態にはしない。

03. PROCESS LOG — 制作ログ

最終形だけでは消えてしまう「分かれ道」を残す。採用した案、捨てた案、A/B、失敗、修正、人間の好みでひっくり返った瞬間。

残したいもの

INTENT / KEY DECISIONS / EXPERIMENTS / REJECTED & WHY / HUMAN FEEDBACK / FAILURES & REPAIRS / DELTAS FROM INITIAL CONCEPT

これはAIの非公開な思考過程を公開する仕組みではない。

会話、Issue、比較結果、採否、テストなど、外から観測できる制作上の意思決定だけを残す。

04. ECOSYSTEM RETURN — 再利用できる知見

その作品だけに閉じない発見があった時、次の制作へ持っていける形にする。デザイン原則、失敗パターン、テンプレート、チェックリストなど。

何もなければ、NOT_NEEDEDでよい。

「作品を作ったから学びも捏造する」ことはしない。再利用できる差分が本当にある時だけ返す。

裏側にある2つ

人に見せる4面とは別に、再開可能性を支える薄い裏方がある。

RESULT

今回やったこと、成果物、発見、残件、接続先、証拠を回収する運用上の封筒。作品の説明文の代わりにはしない。

MANIFEST

各面へのリンクだけを持つ目次。状態の正本にはならない。最後に作る。

最小MANIFEST

これだけあれば、別の日・別の人・別のAIからでも「どこを開けばいい？」を復元できる。

パックが通った、と言える条件

作品を直接開ける。
公開版だけ読んでも何を作ったか分かる。
主要な分岐・失敗・人間の評価を制作ログから辿れる。
残件と再開先がRESULTから分かる。
再利用知見は「採用済み」と「提案」を混同していない。
重要なものがチャットの中だけに残っていない。

やらないこと

・すべての途中版にnoteを書く。

・昔の作品を全部さかのぼってパッケージ化する。

・MANIFESTを新しいDBにする。

・制作ログを生の会話全文にする。

・「公開した」と「生態系に採用された」を同じ意味にする。
